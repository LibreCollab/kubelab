CoreDNS serves names like `web.demo.svc.cluster.local`. Pods resolve Services through the cluster DNS service.

- `<service>.<namespace>.svc.cluster.local`
- A Pod in the same namespace can use the short name: `web`.
- Headless Services expose Pod IPs directly.
- DNS failures often look like connection timeouts.

```bash
kubectl create deployment web --image=nginx --replicas=2 -n demo
kubectl expose deployment web --port=80 -n demo
kubectl run client --image=busybox -n demo
kubectl exec client -n demo -- nslookup web
```

**Failure modes.** DNS failures can come from CoreDNS, the Pod DNS policy, the search path, or a Service with no endpoints. A name can resolve correctly and still produce a failed request. Short names are namespace-relative, so copying a command into another namespace changes the result.

**Verify.** Verify CoreDNS health, the client's resolver configuration, and the full returned name. Inspect Endpoints and test the request from the same Pod that reported the problem. Resolution and connectivity are separate checks and should be tested separately.
